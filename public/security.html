Security Architecture

Built with Defense-in-Depth

Every layer of the stack is designed to eliminate long-lived secrets. No single breach can expose user data.

Cryptographic Primitives

Encryption Specifications

AES-256-GCM

NIST SP 800-38D

256-bit keys, 96-bit random IV, 128-bit authentication tag. Provides confidentiality + integrity in one primitive.

Web Crypto API

SubtleCrypto

Browser-native, hardware-accelerated crypto. Keys never leave the browser in ZK mode. No JS crypto libraries.

PBKDF2

RFC 8018

Passphrase hashing with per-secret random salt. Stored as hash only — the passphrase itself is never persisted.

TLS 1.3

Transport Layer

All traffic is TLS 1.3 encrypted in transit. HSTS headers enforced. No mixed content permitted.

bcryptjs

Admin Auth

Admin passwords are hashed with bcrypt (cost factor 12). TOTP 2FA optionally required for all admin logins.

WAL Checkpoint

SQLite TRUNCATE

After every deletion, wal_checkpoint(TRUNCATE) removes ciphertext residue from the SQLite write-ahead log.

Threat Model

Known Threats & Mitigations

T1 — Unauthorized Public URL Viewer

Server Compromise

Mitigated

In ZK mode, the server only stores ciphertext. A full server compromise exposes only AES-256-GCM ciphertext — useless without the key, which exists only in the URL hash fragment the user shared.

Link Preview Burns

Mitigated

WhatsApp, Slack, Discord, and Telegram send bot crawlers to preview shared links. Bot Guard middleware identifies these by User-Agent and denies the two-step reveal, preventing accidental burns.

Automated Scraping

Mitigated

Rate limiting (30 creates/min, 60 reveals/min per IP), two-step token flow, and non-enumerable 128-bit random vault IDs prevent automated bulk enumeration or scraping.

Passphrase Brute Force

Mitigated

Passphrase protection uses PBKDF2 key-stretching. Auto-destruct can be configured to delete the vault after N failed passphrase attempts.

Data Residue on Disk

Mitigated

PRAGMA secure_delete=ON overwrites deleted SQLite pages. WAL is truncated after every sweep. No ciphertext residue remains on disk post-deletion.

URL Hash Logging

Partially Mitigated

The decryption key lives in the URL fragment (#key=…). Browsers never send hash fragments to servers. However, the recipient's browser history, clipboard manager, or screenshot tool could expose it — a limitation of URL-based key distribution.

XSS / Content Injection

Mitigated

All pages use a strict Content Security Policy, X-Frame-Options: DENY, no-referrer, and sanitize all user-controlled values before rendering. Vault IDs are validated against a hex whitelist before processing.

Admin Session Hijacking

Mitigated

Admin sessions use HTTP-only, Secure, SameSite=Strict cookies. TOTP 2FA adds a second factor. Sessions expire and are invalidated on logout.
