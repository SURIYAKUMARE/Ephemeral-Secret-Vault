2. Threat Actors & Defenses (T1 - T5)

Our security architecture is formally validated against the primary threat actors defined in our security specification:

T1 — Unauthorized Public URL Viewer
Threat: A third party intercepts or receives the vault URL.
Mitigation: The Vault ID alone never leaks the secret. The visitor sees only a safe countdown splash. For high-security secrets, an optional passphrase or IP/geo allow-list gates all access.
T2 — URL Enumeration Attacker
Threat: An automated adversary scans or brute-forces potential vault IDs.
Mitigation: Vault IDs are generated using high-entropy random bytes (not auto-incrementing sequential integers). Rate limiting returns HTTP 429 after 30 requests/minute.
T3 — Browser Inspection & DevTools Attacker
Threat: An attacker opens View Source, DevTools Network, LocalStorage, or console before revealing.
Mitigation: Zero-Plaintext Invariant: Plaintext is never present in initial HTML, CSS, JavaScript files, or browser storage. Only when the recipient clicks "Reveal" is the single-use token exchanged for plaintext.
T4 — Network & Caching Attacker
Threat: Proxies, intermediary caches, or referrers leak the secret or URL.
Mitigation: Strict HTTP headers: Cache-Control: no-store, no-cache, Referrer-Policy: no-referrer, and Strict-Transport-Security prevent caching and referrer leakage.
T5 — Bot Crawlers & Link Preview Scrapers
Threat: Slackbot, Discordbot, Twitterbot, or WhatsApp crawler unfurls the link and prematurely triggers the burn.
Mitigation: Bot defense middleware serves a lightweight static shell to preview crawlers without decrementing views or executing decryption routines.

3. Enterprise Security Capabilities

Shamir's Secret Sharing ($k$-of-$n$): Split critical master keys across $n$ stakeholders requiring a minimum of $k$ distinct shares to reconstruct the secret.
Duress Passphrase Trap: If coerced, entering the duress passphrase returns a convincing decoy cover secret, silently shreds the real secret, and dispatches an emergency webhook alert.
Cryptographically Signed Burn Receipts: Upon secret destruction, an HMAC-SHA256 signed burn receipt is issued with an irreversible cryptographic timestamp for audit compliance.
