How It Works

1. Enter & Configure

Type your credentials, paste confidential keys, or attach files. Choose your expiration time (e.g. 1 hour) and maximum view limit (default: 1 view burn).

2. Encrypted at Rest

Every payload is encrypted using authenticated AES-256-GCM with a fresh cryptographic IV. If a passphrase is provided, it is derived via scrypt.

3. Single-View Atomic Burn

When the recipient opens the link, the server decrypts the payload in memory and immediately executes an atomic SQL burn, wiping it permanently from memory and disk.

Cryptographic Security

Military-Grade Authenticated Encryption

We use standard AES-256-GCM. An authentication tag guarantees that the ciphertext cannot be tampered with in storage.

Zero Plaintext on Disk

Plaintext never touches persistent storage. In-memory buffers are immediately zeroized with buf.fill(0) after transmission.

Passphrase Brute-Force Auto-Destruct

Secrets protected by passphrase automatically hard-delete themselves after 3 failed attempts, accompanied by progressive delay defense.

Crawler & Link-Preview Immunity

Automated chat preview bots (Slackbot, Discordbot, WhatsApp) only receive static metadata shells and never burn secrets prematurely.

Frequently Asked Questions

Can an expired or burned secret be recovered?

No. Once burned or expired, SQLite hard-deletes the row and memory buffers are purged. Recovery is mathematically impossible.

Can chat apps accidentally burn the secret when generating a link preview?

No. Our bot guard intercepts crawler requests and serves a harmless preview shell without triggering decryption or decrementing view counters.

What is the Portable Vault (.html) download?

A portable offline decryptor file that can be saved or emailed. It decrypts client-side in the browser and self-destructs locally after viewing.
